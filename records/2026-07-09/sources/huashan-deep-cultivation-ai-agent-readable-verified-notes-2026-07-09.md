## Data Governance Precision Note

原文「Power BI On-Premises Data Gateway 地端部署，特種個資不出院內網」方向合理，但技術上需更精準。Gateway 是地端資料與雲端服務的橋接層；是否有資料離開院內，取決於資料模型、查詢模式、資料集發佈、報表層是否儲存資料，以及是否只傳輸彙總／去識別化資料。正式資安架構應寫成可稽核的工程條件，而不是僅用一句口號。

原文「SHA-256 單向去識別化」也應細化。對身分證號、手機、病歷號等低熵或可猜測欄位，單純 hash 不足以抵擋重識別。較合理設計是 HMAC-SHA-256 或加鹽雜湊、金鑰與 mapping table 分離、最小必要欄位、權限控管、查詢稽核、報表只輸出彙總資料。

## 壹、計畫總論

### 一、計畫摘要

臺北市立聯合醫院長期配合臺北市政府推動社區健康促進、成人預防保健、老人健康檢查及癌症篩檢等公共衛生服務，為本市重要公共衛生服務執行單位。因應我國正式邁入超高齡社會，慢性疾病、多重共病、肌肉骨骼功能衰退及健康不平等議題日益嚴峻，本院以華山院區為示範場域，提出為期三年之整合性計畫，將院外健康篩檢之數位轉型、高齡功能性風險之AI篩檢，以及民眾健康關係之長期管理，串接為單一閉環照護體系。

本計畫由三個相互銜接的子計畫構成，形成「數位化流程 × 智慧化分層 × 關係化管理」之完整閉環：

- 子計畫一「院外社區健康篩檢數位轉型暨四癌篩檢服務」：汰換運作逾十年之院外篩檢系統，建置電子表單、QR Code快速報到、健保卡驗證、電子簽章、HIS介接之全流程數位化平台；擴大辦理乳癌、子宮頸癌、大腸癌、口腔癌四癌篩檢；建置健康艙標準化量測站及Power BI決策支援（含里級動態風險地圖）；並建立雲端平台與資安架構作為全計畫共用底層。

- 子計畫二「高齡者AI步態與肌少症風險篩檢暨閉環整合照護導流」：以手機或平板攝影之AI動態影像（STS5、TUG、步態）結合BIA、握力、SARC-F等量測，建立肌少症、功能衰退、跌倒三類風險分層模型；以LINE官方帳號取代獨立APP作為居家追蹤入口；依COM-B行為理論分群推送個人化衛教；紅黃綠燈分流導入健服中心課程與聯醫多專業照護。

- 子計畫三「民眾健康關係管理（Health-CRM）」：以PDCA管理循環為方法，整合前兩子計畫之個案資料為單一個案主檔，管理民眾從精準招募、受檢、風險分級、追蹤導流到次年再篩之全生命週期。

計畫三年期，每年經費新臺幣37,500,000元，三年總計112,500,000元。為避免重複編列，全計畫共用之雲端平台、資安架構、Power BI底層由子計畫一統一建置，LINE／LIFF平台由子計畫二建置，子計畫三以增量模組方式沿用，各子計畫預算表均明確標註共用歸屬。所需設備與平台依政府採購法辦理，不預設廠商。

### 二、計畫背景與問題分析

#### （一）政策背景與在地需求

政府推動健康台灣深耕計畫，鼓勵醫療機構導入智慧科技醫療、強化健康資料治理、建構以預防保健為核心之照護模式。本院每年辦理大量院外篩檢活動；隨服務規模擴大，傳統紙本作業與人工管理模式已無法滿足需求，且高齡功能性風險（肌少症、跌倒）在現行篩檢項目中長期缺位。

#### （二）三大結構性缺口

本計畫辨識現行社區篩檢服務之三大結構性缺口，並分別由三個子計畫回應：

- 流程缺口：現行院外篩檢系統建置於民國101年，民眾仍需現場填寫紙本問卷、人工登錄；資料蒐集、資格查核與結果管理缺乏整合平台，現場效率受限、重複輸入、追蹤困難。→ 由子計畫一數位轉型回應。

- 項目缺口：現行篩檢以三高、癌症為主，缺乏肌少症、步態不穩與跌倒風險之功能性篩檢；純社區樣本陽性率偏低（肌少症約8–12%），若無補強設計，AI模型將表面AUC高但實際辨識力不足。→ 由子計畫二AI篩檢與雙軌收案回應。

- 關係缺口：民眾完成篩檢後與醫院關係即中斷；異常個案追蹤依賴人工、缺乏系統性再觸達；篩檢場次設點缺乏數據依據形成覆蓋盲區；成效檢核停留在場次人次等過程指標。→ 由子計畫三CRM關係管理回應。

#### （三）與既有政府補助計畫之區隔

本計畫不重複建置既有系統或重複申請其他部會補助。子計畫一為既有篩檢系統之數位轉型升級，非新建平行系統；子計畫二之AI模型為既有篩檢項目所無之功能性風險辨識，屬新增服務；子計畫三為跨篩檢項目之個案關係整合層，以既有平台產出資料為輸入，屬管理機制創新而非重複性系統建置。

## 貳、子計畫一：院外社區健康篩檢數位轉型暨四癌篩檢服務

（年度經費 18,000,000 元；三年 54,000,000 元。本子計畫並建置全計畫共用之雲端平台、資安架構、Power BI 決策平台底層與健康艙量測節點。）

### 2-1　現況與問題

本院院外篩檢系統建置於民國101年，迄今運作逾十年，受限於舊有系統架構及紙本作業模式：民眾需現場填寫紙本問卷、工作人員人工登錄；篩檢過程之資料蒐集、資格查核及結果管理缺乏整合性平台支援，造成現場作業效率受限、資料重複輸入及後續追蹤管理困難。同時，四癌篩檢（乳癌、子宮頸癌、大腸癌、口腔癌）之陽性個案追蹤多依賴人工名冊，確診轉介完成率無法有效掌握。

### 2-2　數位轉型平台建置

建置涵蓋篩檢前、中、後之全流程數位化服務平台，並以「決標次日起180日曆天完成核心範圍」為契約管控期限：

|                      |                                                                    |
|----------------------|--------------------------------------------------------------------|
| **功能模組**         | **內容**                                                           |
| **預填電子表單**     | 民眾於篩檢前透過連結預填基本資料與健康問卷，減少現場等待與人工登錄 |
| **QR Code快速報到**  | 現場掃碼報到，自動帶入預填資料，串接CRM個案主檔                    |
| **健保卡身分驗證**   | 讀卡驗證身分與篩檢資格，避免重複篩檢與資格錯誤                     |
| **智慧量測設備整合** | 血壓、身高體重等量測設備資料自動回傳，減少人工抄寫誤差             |
| **電子簽章**         | 知情同意與篩檢同意電子化，符合電子簽章法                           |
| **多項篩檢一次建檔** | 成人健檢、四癌篩檢、肌少症篩檢結果統一建檔並回寫個案主檔           |
| **非同步HIS介接**    | 篩檢資料與醫院資訊系統非同步介接，確保系統穩定與資料一致           |

### 2-3　四癌篩檢服務擴大

依國民健康署癌症篩檢政策，於華山院區及社區場域擴大辦理四癌篩檢，篩檢結果即時建檔並回寫CRM個案主檔，陽性個案由CRM追蹤工單啟動確診轉介與追蹤：

|              |              |                                                          |
|--------------|--------------|----------------------------------------------------------|
| **癌別**     | **篩檢方式** | **對象與追蹤重點**                                       |
| **乳癌**     | 乳房X光攝影  | 45–69歲及40–44歲高風險女性；陽性者追蹤影像判讀與切片轉介 |
| **子宮頸癌** | 子宮頸抹片   | 30歲以上女性；異常者追蹤陰道鏡與後續處置                 |

### 2-4　健康艙標準化量測站

建置健康艙2台（固定示範場域1台、行動場域1台），整合血壓、脈搏、身高體重、BMI、生物電阻抗分析（BIA）、握力、SARC-F問卷，輸出QR/PDF個人報告並即時上傳雲端。健康艙資料同時支援子計畫二AI模型之reference standard蒐集，為全計畫共用量測節點。健康艙負責靜態量測，不承擔動態測試（STS5、TUG）安全責任。

| **第1台（固定）** | 聯醫指定示範場域或健康服務中心 | 全年定點量測；BIA校準基準站；高品質reference standard蒐集；HIS串接測試 | 血壓、脈搏、身高體重、BIA、握力、SARC-F、QR/PDF |

### 2-5　Power BI 決策支援與里級動態風險地圖

建置五大核心智慧健康管理指標與里級動態風險地圖，作為全計畫共用之決策底層：以熱區圖呈現各里三高盛行率與篩檢覆蓋率，覆蓋率顯著低於全區均值時自動紅燈警示（辨識公衛防禦盲區）；決策者可鑽取該里年齡層、性別比與危險因子趨勢，精準投放篩檢資源。子計畫三之里級風險地圖以本底層之增量模組方式建置，不重複編列。

### 2-6　雲端平台與資安架構（全計畫共用底層）

- 採Power BI On-Premises Data Gateway地端部署，特種個資不出院內網。

- 落實SHA-256單向去識別化與稽核軌跡；資料存取採角色權限分層控管。

- 符合《個人資料保護法》、醫療法及深耕計畫資安治理自我檢核要求。

- 本架構同時作為子計畫二（AI資料）與子計畫三（CRM資料）之共用底層，不重複編列。

## 參、子計畫二：高齡者AI步態與肌少症風險篩檢暨閉環整合照護導流

（年度經費 17,500,000 元；三年 52,500,000 元。本子計畫建置 LINE／LIFF 居家追蹤平台，供子計畫三 CRM 多通路觸達沿用。）

### 3-1　三類AI模型設計

AI動態影像直接觀察到的是功能表現而非肌肉量本身。為避免單一模型混淆肌肉量、功能與跌倒三種不同構念，本子計畫建立三類獨立模型：

|                      |                                                                      |                                                     |                         |              |
|----------------------|----------------------------------------------------------------------|-----------------------------------------------------|-------------------------|--------------|
| **模型**             | **Ground Truth（Reference Standard）**                               | **主要輸入特徵**                                    | **用途**                | **陽性樣本** |
| **肌少症風險模型**   | BIA/ASMI低於AWGS2025截點；握力偏低；小腿圍偏低；SARC-F≥4（至少兩項） | 影像特徵+BIA+握力+小腿圍+人口學+共病                | 辨識possible sarcopenia | ≥80筆        |
| **功能衰退風險模型** | SPPB≤9分；TUG≥12秒；STS5≥15秒；步速\<1.0 m/s（至少一項）             | STS5/TUG/步態時間、速度衰退斜率、手部輔助、轉身穩定 | 辨識下肢功能衰退        | ≥80筆        |
| **跌倒風險模型**     | 過去一年跌倒≥1次；或近跌倒≥2次；或TUG≥13.5秒                         | 影像特徵+跌倒史+用藥數+疼痛VAS+TUG轉身時間          | 輔助紅燈分流            | ≥60筆        |

### 3-2　陽性率問題與雙軌收案設計

這是本子計畫AI設計最關鍵的統計議題。社區整合性篩檢族群中肌少症盛行率約8–12%、高跌倒風險約15–20%；若僅使用社區樣本建模，陰性個案過多會導致模型傾向全判陰性，表面AUC可達0.85但實際對高風險辨識毫無效益。

|                      |                           |                                  |                                         |
|----------------------|---------------------------|----------------------------------|-----------------------------------------|
| **情境**             | **社區自然陽性率**        | **1,000人中陽性數**              | **模型風險**                            |
| 純社區樣本（無補強） | 肌少症8–12%；高跌倒15–20% | 約80–120人                       | 模型傾向預測陰性；AUC表面高但敏感度不足 |
| 不平衡訓練資料       | 陽性:陰性≈1:9             | 全判陰性準確率仍90%              | 「全猜陰性」AUC可達0.85但無辨識力       |
| 補強後（雙軌）       | B軌補入≥200筆陽性         | 陽性:陰性≈1:4–1:5                | 模型能真正學習陽性特徵；敏感度有意義    |
| **目標（三年）**     | 高風險樣本≥200筆          | 搭配≥700筆完整reference standard | AUC≥0.75且敏感度≥0.75有合理基礎         |

本子計畫採雙軌收案解決此問題：

|          |                                                                      |                                          |                                           |                      |
|----------|----------------------------------------------------------------------|------------------------------------------|-------------------------------------------|----------------------|
| **軌道** | **來源場域**                                                         | **樣本特徵**                             | **主要用途**                              | **三年目標**         |
| **A軌**  | 社區整篩、健康服務中心、指定示範場域                                 | 多為低中風險；代表真實世界分布           | 外部可推廣性；真實世界KPI；分流與追蹤成效 | **篩檢人次≥1,000**   |
| **B軌**  | 復健科、老年醫學、營養門診、養護中心、日照中心、曾跌倒或SPPB低分個案 | 高比例陽性或疑似陽性；年齡偏高、功能偏差 | 提升模型敏感度；補足三類模型陽性標籤      | **高風險樣本≥200筆** |

### 3-3　樣本功效估算（Hanley-McNeil法）

採Hanley-McNeil法（AUC比較）結合Obuchowski校正，設定power=0.80、α=0.05，估算各模型最低樣本需求：

|                    |             |                            |                                            |
|--------------------|-------------|----------------------------|--------------------------------------------|
| **模型**           | **目標AUC** | **最低樣本估算**           | **假設條件**                               |
| **肌少症風險**     | ≥0.75       | 陽性≥80筆；總樣本≥400筆    | 陽性率20%（補強後）；power=0.80；α=0.05    |
| **功能衰退風險**   | ≥0.75       | 陽性≥80筆；總樣本≥400筆    | TUG/SPPB低分為標籤；社區可自然取得部分     |
| **跌倒風險**       | ≥0.72       | 陽性≥60筆；總樣本≥350筆    | 跌倒標籤有回憶偏差；目標保守設定           |
| **合計（含重疊）** | —           | 高風險≥200筆；總資料≥700筆 | 三類模型個案可部分重疊；重疊者記錄多重標籤 |

### 3-4　AI建模流程

- 資料字典與reference standard：確認AWGS 2025截點、SPPB/TUG截點、跌倒史定義；建立缺漏值處理規則。

- 影像前處理：預訓練2D姿態估計模型（如MediaPipe Pose或YOLOv8-Pose）萃取骨架關鍵點；建立影像品質分數；優先保存特徵而非完整影像。

- 特徵工程：STS5（總時間、每次起坐時間、速度衰退斜率、軀幹前傾角、手部輔助）；TUG（總時間、轉身時間、步速變異）；步態（步頻、步幅、對稱性、失衡事件）。

- 模型選擇：小樣本優先使用Logistic Regression、Random Forest、XGBoost/LightGBM、SVM；不在小樣本上直接訓練深度影像模型；評估ensemble。

- 分年驗證：第1年內部交叉驗證；第2年外部或時間切分驗證；第3年校準（calibration curve、Brier score）、封存與分層穩定性分析。

- 模型報告：不只呈現AUC，亦報告敏感度、特異度、PPV、NPV、校準度、決策曲線與年齡/性別/場域分層結果；建立模型卡（model card）。

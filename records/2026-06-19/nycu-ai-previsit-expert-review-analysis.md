## Executive Decision

The expert-review package supports a focused AI-only proposal:

```text
「健康台灣深耕計畫」－泌尿科門診前問診與醫師覆核摘要支持系統
```

The proposal should use the Health Taiwan deep-cultivation section order from
the copied format source, while treating that source's PSA screening plan as
separate urology-submitted content. The NYCU Wu-team content is the governed
門診前問診 / 醫師覆核摘要 package. The strongest review posture is to lead with
範疇三「導入智慧科技醫療」 and use 範疇一「優化醫療工作條件」 as the workforce
and workflow support argument.

The proposal should keep NT$10,000,000 as the three-year AI-only working ceiling
and convert work-package logic into official categories:

| Official category | Three-year planning amount | Role in proposal |
| --- | ---: | --- |
| 人事費 | NT$6,140,000 | PM/RA, KPI evidence, clinical reviewer protected time, schema and AI work, evaluation analyst |
| 業務費 | NT$3,630,000 | workflow review, external expert review, documents, LLM/API/cloud/ASR rental, governance workshops, QI/IRB reserve, surveys |
| 設備費 | NT$230,000 | clinic-owned intake station readiness or equivalent procurement-ready placeholder |
| Total | NT$10,000,000 | 100% mapped to KPI, owner and evidence |

This amount should be presented as a governance and workflow transformation
package rather than a single chatbot cost. The review answer is that the package
builds clinical question governance, traceable intake, one-page physician review,
AI safety review, data/security governance, baseline/evaluation evidence, and
handoff readiness over three years.

## KPI Architecture

The KPI set should be written as reviewable workflow and governance evidence,
not as hard clinical-outcome claims.

| KPI family | Proposed threshold | Evidence |
| --- | --- | --- |
| 摘要閱讀時間 | Y1 design target <=60 seconds; report actual values and distribution | timed reviewer log |
| 醫師有用性 | median >=4/5 | clinician scorecard |
| 最低必要欄位完成/標示率 | >=90% | intake log, schema audit |
| 缺漏欄位可見率 | >=90% | review audit |
| source label 完整率 | 100% | summary line audit |
| unsafe wording unresolved count | 0 unresolved | red-team / QA log |
| staff-friction pass | Y1 walkthrough, Y2 revised pass, Y3 SOP | workflow observation |
| governance readiness | named owner or explicit pending gate | governance checklist |
| KPI-to-budget mapping | 100% | budget workbook |

The strongest wording is that these KPIs align claim, evidence and governance.
Clinical results such as cancer mortality, long-term prognosis or chronic disease
outcomes can remain future research or separately governed outcomes, but should
not be the core measurable promise of this package.

## Proposal Scope Controls

The proposal should describe the supported operating scope first, then list the
activation gates:

| Supported now | Activation gate |
| --- | --- |
| guided intake and source-labeled information collection | clinical owner confirms required fields and patient/staff flow |
| one-page physician-review summary | reviewer evidence confirms usefulness and safe wording |
| missing-field visibility and unknown/missing distinction | schema audit and reviewer correction loop |
| synthetic or approved limited workflow evidence | QI/IRB and data/security route named by the hospital |
| ASR / APP / API readiness | only after confirmed-input, accessibility and procurement conditions are defined |
| future HIS/EMR connection | separate production governance, security, procurement and integration route |

The plan should keep CRM, patient messaging, patient follow-up and PSA SOP
outside this package. The current AI package supports urology visits by
improving visit readiness before the physician encounter.

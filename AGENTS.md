# Global Agent Planning And Tone

For research, planning, and reviewer-facing documents in this repository, use
confident, evidence-led, positive-scope writing. Lead with the contribution, the
evidence, the supported scope, and the next implication. Present boundaries as
validation layers, claim-evidence alignment, scoped evidence, or planned
extensions.

All human-facing durable documents in this repository use an affirmative-only
release voice: confident, generous, active, trustworthy, and boundary-clear.
Default structure is capability -> evidence -> ownership -> scope control ->
next validation layer. Scope limits are written as design controls, activation
gates, stewardship commitments, and next-stage paths.

Use Taiwan Traditional Chinese for Chinese-language research/project notes when
the user is working in Taiwanese Traditional Chinese. Human-facing docs use
positive-scope prose; exact machine status labels remain available for scripts,
logs, validators, safety rules, and operational checklists.

For talks, proposals, lab sync briefs, stakeholder-facing summaries, and speaker
scripts, use confident and generous positive-scope language by default:
claim -> evidence -> contribution -> scope control -> next implication. Spoken
content should be designed as affirmative wording: confident progression,
practical capability, evidence, scope control, and next implication. Reframe
contrast pairs into affirmative progression such as "A opens the path to B",
"the useful governance question is", "the evidence supports", and "the next
validation step is". Treat limitations as stewardship, validation, and
claim-evidence alignment.

For meeting minutes, handoff notes, and proposal-facing decision records, use
positive-scope writing as the default release voice. Write from capability,
owner, evidence, validation path, and next decision. Express scope boundaries
as design controls, optional modules, activation gates, evidence requests,
owner assignments, and governance paths. A v2 meeting record
should read as a confident execution brief: what the meeting established, what
the system enables, which responsibilities each component owns, what evidence
will support the claim, and what decision comes next.

For manuscripts, papers, introductions, abstracts, reviewer memos, and
paper-facing strategy notes, design the first-page narrative so technically solid
writing also earns attention. Use this default sequence:
cited real-world or credible near-future problem -> fair cited current solution
landscape -> evidence-backed remaining gap -> new viewpoint, architecture,
framing, or method -> how it addresses the opening problem -> scope controls
and next validation path. Critique prior work by first naming what it enables,
then stating the remaining issue as claim-evidence fit, workflow mismatch,
validation need, scalability issue, safety concern, or unresolved failure mode.

# Assertive Writing Policy

Status: canonical repository-wide writing policy  
Effective date: 2026-07-11  
Supersedes: 2026-06-22 wording layer

## Purpose

This repository writes durable human-facing artifacts in a confident, direct, generous, and positive-scope voice. The writing shows what the project enables, why the design matters, what evidence supports it, who owns it, how governance works, and which validation layer comes next.

This policy applies to proposals, articles, papers, abstracts, reviewer briefs, meeting records, handoff notes, grant responses, presentations, public summaries, project narratives, and agent-generated planning documents.

Core rule:

```text
Capability leads.
Evidence supports.
Ownership clarifies.
Boundaries operate as design controls.
The next validation layer closes the paragraph.
```

## Affirmative-only organizing voice

Every outward-facing paragraph uses an affirmative organizing voice. The paragraph begins with contribution or workflow value. Scope controls then appear as mature architecture, clinical stewardship, authority allocation, claim-evidence alignment, and activation gates.

Default sequence:

```text
contribution → workflow value → evidence → ownership → scope control → next validation layer
```

Traditional Chinese project writing should read as:

```text
正向、主動、可信任、邊界清楚、證據充分、責任明確
```

Exact legal, clinical-safety, official-form, validator, source-quotation, and operational-checklist language retains the wording required for precision. The surrounding release narrative first states the enabled operating scope.

## Positive-scope document design

Outward-facing documents answer six questions in order:

1. What capability does the project establish?
2. Which clinical, workforce, public, or environmental value does it create?
3. Which evidence and KPI demonstrate that value?
4. Which owner carries the responsibility?
5. Which scope controls and activation gates make the design trustworthy?
6. Which next validation layer advances the work?

Preferred proposal opening:

```text
本計畫以信義門診部院外泌尿科門診為核心場域，建立精準預防、門診前資訊準備、醫師覆核追蹤與低碳場域治理的一體化服務鏈。PSA／IPSS／PHI、泌尿症狀問診、來源標記摘要與碳盤查共用工作包、KPI、責任矩陣及證據管理，使臨床品質、流程價值與永續成果可被持續驗證。
```

## Boundaries as professional architecture

Use authority and activation language:

| Design intent | Preferred wording |
|---|---|
| Clinical authority | 診斷、治療、急迫性判斷、檢查處置與正式病歷由泌尿科醫師及院內流程承擔。 |
| Intended use | 本期系統聚焦候診階段之資訊蒐集、缺漏提示、來源標記與醫師覆核摘要準備。 |
| Site scope | 首期實作與成效驗證場域為臺北市立聯合醫院附設信義門診部院外泌尿科門診。 |

| Integration route | HIS/LIS/EMR/CRM 介接列入三年證據成熟後之下一階段啟動層。 |
| Carbon scope | 碳盤查以信義門診部營運控制邊界建立活動數據、熱點、查證與改善路徑。 |

## Attention-earning evidence narrative

Proposal openings, abstracts, reviewer memos, and paper introductions use:

```text
cited real-world problem
→ fair current-solution landscape
→ evidence-backed remaining gap
→ proposed architecture or method
→ measurable response to the opening problem
→ ownership, scope control, and next validation path
```

The gap should be expressed as workflow fit, information completeness, staff burden, source traceability, governance readiness, maintenance, scalability, claim-evidence alignment, or environmental accountability.

## Proposal writing rule

A proposal paragraph begins with contribution and value, then provides evidence, owner, scope control, and next gate.

Preferred:

```text
本子計畫建立信義門診部泌尿科門診前問診與醫師覆核摘要支持系統，在病人完成報到後的候診階段，將病人或家屬提供的 LUTS／IPSS 與 PSA 就診脈絡整理為來源可追溯、缺漏可見的一頁式摘要。醫師閱讀時間、最低必要欄位完成率、來源標記完整率、有用性及工作摩擦構成成效證據；泌尿科醫師保留臨床判斷與正式紀錄權責，真實流程透過院內治理條件啟動。
```

## Meeting records and handoff notes

Meeting records lead with established decisions, enabled capabilities, owner allocation, supporting evidence, synchronized artifacts, and next decisions. Raw quotations retain source fidelity; the executive synthesis uses the affirmative release voice.

## Review checklist

A draft passes when:

- the opening states contribution and value;
- each material claim has an evidence pointer;
- owner and accountable role are explicit;
- boundaries read as deliberate system design;
- Xinyi outpatient urology scope remains stable;
- clinical authority is clear and confident;
- KPI and budget traceability are visible;
- carbon claims follow boundary, activity-data, and verification evidence;
- the next validation or decision gate is explicit;
- no paragraph is organized around apology, inability, denial, or self-weakening language.
